---
title: Schemas
description: How entries are validated and what Qino adds or reserves.
---

Every primitive takes a `schema`. Qino accepts any [Standard Schema](https://standardschema.dev) validator and treats it as a black box: it calls the standard validate function and never touches validator-specific APIs. Zod, Valibot, and ArkType all work.

The schema must be synchronous. A validator that returns a Promise is rejected.

## What the schema receives

For Markdown, MDX, and `.markdown` files, the input is the parsed frontmatter only:

```ts title="Schema input for hello-world.md"
{
  title: "Hello",
  draft: false,
}
```

For `.json` files, the input is the parsed object as-is.

A file without frontmatter validates `{}`, so an empty schema like `z.object({})` is enough. Schemas are required even then.

To reshape data, such as splitting a string or renaming keys, use your validator's transform. See [Transforming data](/docs/concepts/pipeline#transforming-data).

## markdown and raw

After validation, Qino adds two strings to every Markdown entry, like it adds `_meta`:

- `markdown`: the body, without frontmatter. An empty body is an empty string.
- `raw`: the whole source file, frontmatter included, byte for byte.

```ts title="Entry for hello-world.md"
{
  title: "Hello",
  draft: false,
  markdown: "The body, without frontmatter.",
  raw: "---\ntitle: Hello\ndraft: false\n---\nThe body, without frontmatter.",
  _meta: { slug: "hello-world", fileName: "hello-world.md", filePath: "/abs/path/posts/hello-world.md" },
}
```

Don't declare them in the schema; they never reach it, so strict objects work as-is. They are added before views run, so `augment`, `filter`, and `sort` can read them. To derive something from the body, use [`augment`](/docs/concepts/views).

In Markdown files, `markdown` and `raw` are reserved at the top level of frontmatter, schema input, and schema output. Declaring them in a schema is a type error, and frontmatter or a transform that introduces them fails at runtime. Augment callbacks cannot add or replace them either. In JSON files, both are ordinary fields.

## Reserved: \_meta

`_meta` is reserved at the top level of content, schema input, and schema output, for every format. Declaring it in a schema is a type error. A transform that introduces it fails at runtime. Nested keys named `_meta` are ordinary fields.

After validation, Qino adds `_meta`:

| Primitive  | `_meta` fields                 |
| ---------- | ------------------------------ |
| Collection | `slug`, `fileName`, `filePath` |
| Tree       | `slug`, `fileName`, `filePath` |
| Item       | `fileName`, `filePath`         |

## Dates

YAML never produces `Date` objects on its own. Validate date strings with `z.iso.date()` or coerce with `z.coerce.date()`. See [Frontmatter](/docs/guide/frontmatter).

## Validation errors

A failing entry throws with the file path and every issue:

```txt title="Terminal"
Validation failed for /abs/path/posts/hello.md:
  title: Invalid input: expected string, received undefined
```

`qino check` runs the same validation for every file. See [CLI](/docs/guide/cli).
