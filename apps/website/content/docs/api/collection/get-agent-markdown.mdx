Builds the agent Markdown of an entry page, the document served to agents in place of the page. Without a slug, it builds the index page's. The collection must declare [`pages`](/docs/api/collection#pages).

```ts title="src/routes/blog.$slug.tsx"
const post = await postCollection.getAgentMarkdown("hello-world");
const blog = await postCollection.getAgentMarkdown();
```

## Signature

```ts title="@qino/cms"
collection.getAgentMarkdown(slug: string, options?: { view?: ViewName }): Promise<string | null>;
collection.getAgentMarkdown(): Promise<string>;
```

## Parameters

| Name           | Type      | Required | Default     | Description                                                                                                                   |
| -------------- | --------- | -------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `slug`         | `string`  | no       |             | The entry's slug. Any string, such as a route param. Leave it out for the index page                                          |
| `options.view` | view name | no       | `"default"` | The view whose `filter` decides if the entry is shown, and whose `augment` can add its title or description. Entry pages only |

## Returns

For an entry page, `Promise<string | null>`:

- `# {title}`, from the `title` field and falling back to the slug, then `> {description}` when the `description` field holds one, then the body without frontmatter.
- No heading when the body opens with its own H1.
- Site-relative links and images made absolute on `siteUrl`, and MDX components replaced through [`agentMarkdown.components`](/docs/api/types/agent-markdown-component).
- The heading only for a JSON entry.
- `null` when no entry has the slug, `""` included, or the view's `filter` excludes it. Unlike [getEntry](/docs/api/collection/get-entry), it doesn't throw for these.

For the index page, `Promise<string>`: `# {pages.title}`, then a link per entry in the default view's order, as `- [title](Markdown URL): description`. With no entries, it's the heading alone. It takes no view.

```md title="https://www.qino.works/blog.md"
# Blog

- [Why another Content Management System?](https://www.qino.works/blog/why-another-cms.md): Coding agents work best with content they can read.
```

## Throws

- `Collection "<directory>" has no pages: declare them to get agent Markdown and Markdown URLs.`
- `Unknown view "<name>". Available views: <names>.`
- Validation, relation, augment, and component function errors. See [Errors](/docs/api/errors).
