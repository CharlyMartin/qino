---
title: Cloud
description: Configure how the Qino cloud UI publishes, searches, sorts, hides fields, and handles media.
---

The Qino cloud UI lets editors change content without touching code. Its only contract with your project is `qino/_generated/config.json`. Set `cloud` on [`initQino`](/docs/api/init-qino) and `qino build` writes that file, including the cloud options below. See [Config file](/docs/guide/cli#config-file).

```ts title="qino/index.ts"
import { initQino } from "@qino/cms";

export default initQino({
  contentFolder: "src/content",
  mediaFolder: "public",
  cloud: {
    publish: { mode: "open_pull_request", reviewBeforePublish: true },
    media: {
      accepted: [
        { type: "image/webp", maxSize: "5MB" },
        { type: "image/png", maxSize: "5MB" },
      ],
    },
  },
});
```

## Publish

`publish.mode` decides what happens when an editor publishes:

- `"open_pull_request"`: the cloud UI pushes a branch and opens a pull request. Branches start with `branchPrefix`, `"qino/"` by default.
- `"commit_to_default_branch"`: the cloud UI commits to the repository's default branch. `branchPrefix` is a type error here.

`publish.reviewBeforePublish` is required. When `true`, an approver signs off in Qino before the author can publish, in either mode.

Pass an object instead of `true` to configure review. `bypassIfAdmin` lets admins publish before every entry is approved, `false` by default:

```ts title="qino/index.ts"
publish: {
  mode: "open_pull_request",
  reviewBeforePublish: { bypassIfAdmin: true },
},
```

In `config.json`, `reviewBeforePublish` is `false`, or its settings with defaults filled in: `true` becomes `{ "bypassIfAdmin": false }`.

Until an editor publishes, edits are saved as drafts in the cloud UI, not in the repository.

## Media

`media.accepted` lists the file types editors can upload. Each entry has a MIME `type`, wildcards allowed (`"image/*"`), and a `maxSize` from `"50KB"` to `"950KB"` in steps of 50, or `"1MB"` to `"100MB"`, where 1KB is 1024 bytes. Anything else, like `"1.5MB"` or `"25KB"`, is a type error. `config.json` holds it in bytes, so `"5MB"` becomes `5242880`. Unset, it's left out of `config.json` and the cloud UI accepts any type up to 5 MB. `[]` disables uploads.

## Primitives

Each primitive takes its own `cloud` option. Setting it without `cloud` on `initQino` throws at definition.

```ts title="qino/collections/posts.ts"
export const postCollection = qino.defineCollection({
  directory: "posts",
  extension: ".md",
  schema: z.object({
    title: z.string(),
    draft: z.boolean(),
    cover: z.string(),
    notes: z.string().optional(),
  }),
  cloud: {
    displayAs: "Blog posts",
    displayEntryAs: "{title}",
    saveAs: "{title}",
    searchableBy: ["title"],
    sortableBy: ["title", "draft"],
    hiddenFields: ["notes"],
    media: { saveAs: "posts/{name}-{hash}", fields: ["cover"] },
  },
});
```

| Option           | Collections | Trees | Items | Default                     | Description                                                                                                                                |
| ---------------- | ----------- | ----- | ----- | --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `displayAs`      | yes         | yes   | yes   | The id                      | Name of the primitive in the cloud UI, such as `"Blog posts"`. A plain string, without tokens                                              |
| `displayEntryAs` | yes         | yes   |       | `"{<titleField>}"` on trees | Label of entries in the cloud UI, from their fields, such as `"{firstName} {lastName}"`. Unset on collections, the cloud UI shows the slug |
| `saveAs`         | yes         | yes   |       |                             | Name of new entries, from their fields, such as `"{firstName}-{lastName}"`. Unset, editors type the slug                                   |
| `searchableBy`   | yes         | yes   |       | `[]`                        | Top-level fields the cloud UI searches. Empty, there's no search                                                                           |
| `sortableBy`     | yes         |       |       | `[]`                        | Top-level string, number, or boolean fields the cloud UI sorts by. Empty, no sorting                                                       |
| `hiddenFields`   | yes         | yes   | yes   | `[]`                        | Top-level optional fields the cloud UI doesn't show. Their values are kept on save                                                         |
| `media.fields`   | yes         | yes   | yes   | `[]`                        | Paths to string fields edited with a media picker, such as `"gallery[*]"`                                                                  |
| `media.saveAs`   | yes         | yes   | yes   | `"{id}/{name}-{hash}"`      | File path an upload is saved to when publishing, relative to `mediaFolder`                                                                 |
| `media.accepted` | yes         | yes   | yes   | `initQino`'s                | Replaces `initQino`'s list for this primitive. `[]` disables uploads                                                                       |

Trees are ordered by their order file, so they have no `sortableBy`. Items are a single file, so they have no `saveAs` or `displayEntryAs`, and only take `displayAs`, `hiddenFields`, and `media`.

Fields are typed against the schema input, not its output, since the cloud UI reads files on disk: with a transform that renames `created-on` to `createdOn`, use `"created-on"`. Fields whose input is `unknown`, such as `z.coerce.date()`, can't be sorted by. `qino build` checks the same rules against the schema's JSON Schema, and also fails when a `sortableBy` field allows a non-scalar value in any union branch.

### Naming new entries

`saveAs` names the file of an entry an editor creates, from its fields. Each `{token}` is a top-level field, filled with the value the editor enters, then slugified. Text outside tokens is kept:

| `saveAs`                   | Fields                                 | File                  |
| -------------------------- | -------------------------------------- | --------------------- |
| `"{firstName}-{lastName}"` | `firstName: "Jane"`, `lastName: "Doe"` | `jane-doe.json`       |
| `"post-{title}"`           | `title: "Hello, World!"`               | `post-hello-world.md` |

The cloud UI adds the extension, and in trees the parent folder, from where the entry is added in the outline: `"{title}"` names a child "Caching" under `guides` `guides/caching.mdx`. When the name is taken, it adds `-2`, `-3`, and so on. The name is set once, when the entry is created. Unset, editors type the slug.

Tokens must be fields every entry has: required, without a default, in every variant of a union schema, and a string, number, or boolean. `saveAs` is type-checked from its literal, so an unknown or optional field, a `/` or `.`, or a pattern without a token is a type error. `qino build` checks the same rules, including for a `saveAs` passed as a `string` variable, which types can't check.

### Naming primitives and entries

`displayAs` names the primitive itself, such as `"Blog posts"` for the `posts` collection, where the cloud UI lists primitives and titles their pages. It's a plain string: `qino build` fails on an empty one or one with a `{field}`. Unset, it's the id: the `directory`, or the `file` of an item. An item is a single entry, so `displayAs` names that entry too.

`displayEntryAs` is how the cloud UI labels each entry of a collection or tree, from its fields. It uses the same `{token}` syntax as `saveAs`, but values aren't slugified, and text outside tokens can be anything:

| `displayEntryAs`            | Fields                                 | Label           |
| --------------------------- | -------------------------------------- | --------------- |
| `"{firstName} {lastName}"`  | `firstName: "Jane"`, `lastName: "Doe"` | `Jane Doe`      |
| `"{lastName}, {firstName}"` | `firstName: "Jane"`, `lastName: "Doe"` | `Doe, Jane`     |
| `"Post: {title}"`           | `title: "Welcome"`                     | `Post: Welcome` |

Unset, collections' entries show their slug, and trees fall back to `titleField`, which titles nodes in `getTree` too. Tokens follow the same rules as `saveAs`'s: required fields every entry has, and strings, numbers, or booleans. They're type-checked from the literal, and `qino build` checks them too.

### Hidden fields

`hiddenFields` only takes optional fields, `.optional()` or `.default()` in zod, so editors can still create entries: a required field is a type error, and `qino build` fails on one without a default. Hidden fields can also be in `searchableBy` and `sortableBy`, but never in `saveAs` or `displayEntryAs`, whose fields are required.

### Media fields

`media.fields` uses the [relation path](/docs/concepts/relations#declaring) syntax, so media fields can be nested: `"image"`, `"gallery[*]"` for each string of an array, `"seo.image"` for an object field. Each path must lead to a string. A path can't also be a relation: a field holds either a media URL or a reference.

The cloud UI writes the URL the file is served at, starting with `/`: picking the upload saved at `public/posts/cover-1a2b3c4d.webp` writes `"/posts/cover-1a2b3c4d.webp"`. That's the URL [`qino check`](/docs/guide/cli#media) resolves against `mediaFolder` to find missing files.

### Saving uploads

When an editor publishes, each uploaded file is saved to the path `media.saveAs` describes, relative to `mediaFolder`. As with entries' `saveAs`, the cloud UI adds the extension: the uploaded file's, lowercased. With `mediaFolder: "public"` and `saveAs: "posts/{name}-{hash}"`, uploading `Cover.webp` saves `public/posts/cover-1a2b3c4d.webp`, served at `/posts/cover-1a2b3c4d.webp`. Tokens:

| Token    | Value                                                                      |
| -------- | -------------------------------------------------------------------------- |
| `{id}`   | The primitive's `directory`, or its `file` without the extension for items |
| `{name}` | The uploaded file's name without its extension, slugified                  |
| `{hash}` | The first 8 hex characters of the file's SHA-256                           |

With `{hash}`, an upload never overwrites another file, and each URL always serves the same content, so it can be cached for good. `qino build` fails on an unknown token, a `.` in the file name, a path ending with `/`, or a path starting with `/` or containing `..`.

## In config.json

`config.json` holds every value resolved, so the cloud UI doesn't reimplement defaults: `branchPrefix`, `reviewBeforePublish`'s settings, and `media.saveAs` are filled in, lists default to `[]`, and each primitive's `media.accepted` falls back to `initQino`'s. It's left out when neither sets it. `displayAs` and `displayEntryAs` sit at the top level of the primitive, next to `titleField`. `displayAs` defaults to the id, and trees' `displayEntryAs` to `"{<titleField>}"`. Collections leave `displayEntryAs` out when unset.

```json title="qino/_generated/config.json"
{
  "cloud": {
    "publish": {
      "mode": "open_pull_request",
      "reviewBeforePublish": { "bypassIfAdmin": false },
      "branchPrefix": "qino/"
    }
  },
  "collections": {
    "posts": {
      "displayAs": "Blog posts",
      "displayEntryAs": "{title}",
      "cloud": {
        "searchableBy": ["title"],
        "sortableBy": ["title", "draft"],
        "hiddenFields": ["notes"],
        "media": { "saveAs": "posts/{name}-{hash}", "fields": ["cover"] }
      }
    }
  }
}
```
