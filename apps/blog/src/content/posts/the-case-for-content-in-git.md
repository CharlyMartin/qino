Putting content in Git sounds like an engineering compromise — *we'll let writers learn Git* — but the value flows the other way. Writers benefit from the things engineers have taken for granted for years.

Branching for drafts. Pull requests for review. Diffs that show *exactly* what changed in a paragraph. Reverting a regrettable edit with a one-line command.

> The best argument for content in Git isn't technical. It's that "track changes" is finally something a machine can reason about.

The friction is the UI, not the model. Hide Git behind a friendly editor and writers stop noticing it's there.
